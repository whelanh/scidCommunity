## What this is

#437 §3b: the **Tactics puzzle trainer** (`tcl/tools/tactics.tcl`) moves off the
legacy `::uci` engine mode onto its own `::engineNoWin` connection.

This is not the wiki's "TacticalMode" and it does not duplicate Play versus
Engine. `tactics.tcl` is the puzzle solver over a tactics base: it keeps its
per-position progress in the PGN `Site` token, gives the player one position at
a time, and referees the answer against the engine's best line. §4 ports
`sergame`; this PR does not touch it, and it does not delete anything.

## Base

Three commits on `github` @ `2ebefb4b`, the merge of §3a (#466). §3a added
`tests/tcl/tactics_trainer.tcl` with the old engine layer stubbed
(`::uci::startEngine` on slot 5, `::uci::sendToEngine`, the `::analysis(multiPV5)`
row); §3b deletes exactly that layer, so the harness that lands here is the one
§3a shipped, rewritten against the trainer's own connection. Nothing else moves.

## The port, measured

`tcl/tools/tactics.tcl`: 4 `::uci::` references and one `::analysis(` read
become **one** `::uci::` reference, the PV formatter it still legitimately
calls, and **none** of the array. The inventory's row for this file is now
stale; `docs/analysis-engine-inventory.md` gains the measured delta so §6 has
the call site without re-deriving it.

- **Connection.** `::engineNoWin::initEngine` with the documented literal id
  `tacticsTrainer`. `initEngine` `cd`s to the preset's `Dir`, sends the preset's
  `UCIoptions` and keeps `engConfig_$id`; the id is a caller-chosen string (no
  allocator exists at `aceb0dc4`), and every other client passes a literal too.
  A stale connection under that id is closed first, because `initEngine` answers
  1 without connecting when `engConfig_$id` already exists.
- **MultiPV.** Asked for on the trainer's own connection after init
  (`SetOptions {{MultiPV 1}}`), never through `::enginecfg::setOption`, which
  writes the preset and restarts the user's own search. One line is all the
  referee reads: the old code also read index 0 only.
- **The live line.** `::enginecomm` drops the info lines that arrive after a
  stop request, so the trainer keeps the best line while it streams and
  `stopAnalyze` snapshots what the timer found. This is the one place where the
  port had to change shape rather than translate: the old mode read the
  Analysis window's `multiPV` row *after* sending `stop`.
- **One Go message.** The position and the infinite limit travel together
  (`Go {position fen <fen> infinite}`). `::enginecomm` replaces a search that is
  still running, which is what the old explicit `exit`/`stop` pair was for, and
  a stale `position` can no longer be paired with the next `go`.
- **Score.** The referee's comparison is untouched, and the conversion it
  depends on is now written down as `::tactics::whiteScore`: White's point of
  view, in pawns, a mate as the ±327.xx sentinel its distance produces. That is
  the same arithmetic the legacy analysis reader did, including the ±1/100
  adjustment around a mate.
- **SAN.** Still the tree's formatter: `::uci::formatPv $pv $fen` today, the
  call §6 moves to `::ucifmt::` together with every other call site. No interim
  module, no copy.

## Strings

Two new user-visible messages, keyed in all **29** catalogues:

```
TacticsEngineStartFail   Could not start the tactics engine: %s
TacticsEngineGone        The tactics engine stopped: %s
```

Both replace hardcoded English: the old start failure popped "Unable to start
the program" from `uci.tcl`, and a dead engine wrote to a closed pipe.

The `Training: Tactics` help page is kept and no longer describes the old
engine/analysis machinery: it says the trainer starts its own engine for the
session, closes it with the window, offers the configured UCI engines, and the
`Seconds per move` slider bounds the search. (The page used to call that slider
"Limit engine analysis time", which is a different option.)

## Retired or changed shape

No user-visible feature is retired by this PR: Tactics keeps its Training menu
entry, its help page, its base dialog, its clock, `Win won game`,
`Show solution`, `Reset scores`, `Next` and `Abort`.

What changes shape inside:

- the trainer no longer takes Analysis engine slot 5, so a puzzle cannot collide
  with an open Analysis window and closing that window cannot kill a puzzle;
- a preset that cannot start is reported with a translated message instead of
  the untranslated box from `uci.tcl`;
- an engine that dies mid-puzzle now closes the session and says which engine
  stopped, instead of leaving the last line on the label and erroring in a
  background handler.

## Review fixes

Two defects reported on review, both fixed in this branch:

- **The second wait had no window guard.** When the engine died mid-analysis,
  `engineGone` cleared `analyzeMode` and destroyed `.tacticsWin`, and the wait
  resumed into a closed session — a bogus "Best solution NOT found", `sc_move
  back` and a save on a destroyed window. The first wait's one-line guard is now
  on both. The asymmetry is older than this PR: the base at `2ebefb4b` has it
  too, and it is fixed here because this is the change that rewired `engineGone`.
- **A search that measured nothing was published as a result.** The search state
  is a dict whose `score` starts empty, and `stopAnalyze` published it whenever
  the dict was non-empty — which it always is. A timer that expired before the
  first `InfoPV` therefore handed the referee an empty score, and `foundBestLine`
  raises on `""` inside an `after` handler, stalling the loop. `stopAnalyze` now
  records that nothing was measured, and `mainLoop` stops without judging — it
  does not reschedule, because `noLine` is cleared only by `startAnalyze` further
  down the loop, so a retry there would re-enter the same branch forever, and a
  re-arm from the second wait would set `prevScore` from the analysis it is about
  to start.

## Notes for the later phases

- Connection ids are literals in one flat `::engconn(...)` namespace
  (`epdAnalysis`, `tacticsTrainer`, `::finishgame::WhiteId`, the review
  one-shots). §4's per-connection state has to live alongside them without
  colliding.
- The trainer's `vwait` is on its own timer flag, not on an engine reply:
  `stopAnalyze` clears it from the timer it armed, so the wait ends even if the
  engine never answers. §6 can delete the reply machinery without touching it.
- After this PR, the only file left that drives `uci.tcl`'s play path
  (`::uci::startEngine`) is `sergame.tcl` (§4). §6 is gated on §5 as well:
  `tcl/tools/analysis.tcl` still calls five procs of the retiring pipe mode —
  `processAnalysisInput` (:1617), `sendUCIoptions` (:1648, :1687), `whenReady`
  (:1650, :1689), `sendStop` (:2371), `sendPositionGo` (:2808) — and it is
  §5's deletion target. `tactics.tcl` keeps one call into `uci.tcl`: the PV
  formatter §6 relocates.
